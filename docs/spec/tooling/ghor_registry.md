# ghor Registry

`ghor` supports filesystem, HTTP, sparse HTTP and Git registry transports. Mutating
operations are available for filesystem and authenticated HTTP registries.

Registry layout:

```text
registry/
  index.json
  packages/
    package_name/
      version/
        package_name-version.crate
        manifest.json
  <cargo index path>
  registry-audit.json
```

The `.crate` is generated by nC stage1 as deterministic GZIP/DEFLATE/USTAR bytes.
`publish` transports those exact bytes, their SHA-256 checksum and `manifest.json`.
No host archiver or Rust materialization command participates in the native route.

The registry index records name, version, checksum, material paths, metadata, owners,
yank state and verification. Mutations use lock, temporary and backup files, recover an
interrupted index transaction, maintain the Cargo package index path and append an audit
event. An absent index is valid for a new filesystem registry and is created atomically.
