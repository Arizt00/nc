# ncc Binary Versioning Priority 11 Contract

Status: closed for the current CLI surface.

Priority 11 prevents multiple `ncc` binaries from silently drifting across
WSL, Ubuntu, Kali, PowerShell or CMD paths.

## Commands

```bash
ncc --build-hash
ncc --build-hash --json
ncc --version
ncc doctor bins
ncc doctor bins --json
ncc update --all-paths --dry-run --json
ncc update --all-paths --yes
```

## Guarantees

- `--build-hash` hashes the exact executable returned by `current_exe()`.
- `--version` prints package version, executable path and build hash.
- `doctor bins` reports the exact binary being executed.
- `doctor bins` scans `PATH` for `ncc` and managed tool binaries.
- Duplicate candidates are reported as `duplicates_detected`.
- Candidates with different executable hashes are reported as
  `hash_mismatch_detected`.
- If the binary being executed is not one of the candidates reachable through
  `PATH`, `doctor bins` reports `current_not_on_path`; if that hidden PATH
  candidate has a different hash, the global status is `hash_mismatch_detected`.
- `doctor bins --json` reports `host_os`, `host_arch`, `host_family`,
  `exe_suffix`, `path_separator`, `path_roots`, candidate file names, PATH roots
  wrapper type (`.cmd`/`.bat`) where applicable, `current_in_path_candidates`
  and per-bin `current_not_on_path`.
- `update --all-paths` detects every PATH root exposing `ncc`.
- `update --all-paths` shows update weight before touching binaries.
- Non-dry-run update still requires explicit authorization or `--yes`.

## Negative Boundary

`doctor bins` does not delete or reorder PATH entries. It reports the problem,
including duplicated paths and mismatching build hashes, and points to
`ncc update --all-paths`.

`doctor bins` treats Windows `.cmd`/`.bat` launchers as real PATH candidates and
marks them with `is_windows_wrapper` so PowerShell/CMD shims cannot hide a stale
WSL or Linux binary behind an apparently valid `ncc` command.

When a wrapper contains a quoted native `.exe` target, `doctor bins` reports it
as `wrapper_target` and compares that executable's SHA-256. The wrapper text is
not incorrectly compared with machine-code bytes.

Windows wrappers generated by `ncup update powershell|cmd` are host neutral:
they prefer a native `ncc.exe` when present, then try `NCC_WSL_DISTRO`, then the
configured distro, then common WSL names such as `Ubuntu`, `kali-linux`,
`Kali-Linux`, `kali` and `Debian`. This keeps IDE Run buttons and terminal calls
working across CMD, PowerShell, WSL and Kali without changing source files.

`update --all-paths --dry-run` is observational. It does not modify binaries.
